# Print content audit and saved templates

## Purpose

Detect **current project content silently omitted by an older custom layout**. Example: a bund template is saved, turfing is subsequently added in the frontend, but that template never prints the turfing contribution. This is not an inventory of every Typst variable. Paper size, margins, fonts, spacing, colours, intermediate calculations and internal configuration are not printing obligations.

The executable checklist is `src/renderer/src/lib/typist-output/printContentAudit.ts`. It builds obligations from current compiler JSON, independently of the selected source. Never derive required content by scanning the custom source: omitted content would then disappear from both the print and its checklist.

## Saving

Each studio has its own `printStudioDocuments[scopeKey]` inside the `.eestimate` project. On first opening, its initial built-in source is put into project state so an ordinary project save includes it. Studio Save writes the edited source and saves the project file; canceled/failed disk saves must not mark the editor saved. Reopening uses that saved source. Empty or invalid saved source is still user source; do not fall back silently.

**Use default** resets the editor to the built-in source. Save persists that reset. There is no user-defined default and no Set as default operation. Updated project data must not replace saved layout code. Any migration that changes a saved layout needs an explicit user-facing action, not an unconditional source rewrite during opening or printing.

## Initial acceptance inventory (contract v1)

Paths below are relative to the indicated runtime object. Each array entry is checked separately, using a path scoped to that compile input. Repeated values or duplicate material codes cannot satisfy another record. IDs are recomputed per compile, not persisted identities; never compare them across different data snapshots.

| Studio / current templates | Required content | Acceptance |
| --- | --- | --- |
| Bund (`bund/bund.typ`) | `sections[]`, `payable_by_code[]`, `excavation_by_code[]`, each payable `terms[]`, `berms[]` | Every section is represented in the quantity statement; every payable code and each contributing work has its quantity printed; each configured berm has its detail card. Turfing creates a payable contribution even if its code is shared. Grouped totals alone do not satisfy omitted contributions. |
| Guide wall (`guidewall/guidewall.typ`) | `figures[]`, `wall_groups[]`, `base_groups[]`, each group's `rows[]`, `excavation.rows[]` | Each figure/group and each measurement row appears. Quantity markers belong to the actual quantity cells. |
| Lead (`lead.typ`, map block generated by `leadTypst.ts`) | `materials[]`, `breakdowns[]`, each breakdown's `steps[]`, `map` when available | Each material, detailed calculation and step appears; the saved available map is included. No available map means no map obligation. |
| Seigniorage (`seigniorage.typ`) | Each `material_groups[].rows[]` | Each applicable material's quantity row appears. An empty group creates no material obligation. `seigniorage-legacy.typ` is compatibility source, not the current acceptance baseline. |
| Data / rate analysis (`data.typ`) | `sor[]`, `recipes[]`, each recipe's `materials[]`, `machinery[]`, `labour[]`, `leads[]` | Every analysis and visible frontend-selected cost row appears. Explicit frontend visibility flags suppress corresponding cost-row obligations; custom code cannot suppress them. |
| Component (`component.typ`, `univerComponent.typ`) | `abstract[]`, non-template-generated `items[]` | Every abstract item appears, plus details of every external/manual item. Bund/guide-wall generated details are checked by those contracts, avoiding duplicate generic detail obligations. |
| General abstract (`project.typ`) | `lines[]` | Every computed abstract work/adjustment line appears, including new lines. |
| Item spreadsheet (`item.typ`, `univerSheet.typ`) | Nonempty cells of the first sheet, within explicit frontend print range, excluding hidden rows and covered merged cells | Each selected cell's content is rendered. Zero is content. Styles alone are not content. A custom narrower range does not remove frontend-selected obligations. |
| Item document / supporting page (`itemdoc.typ`, `univerDoc.typ`) | Nonblank parsed `paragraphs[]` (including table paragraphs) | Every selected content paragraph appears. The frontend document print-area parser defines the selected body before auditing. |
| Cover (`cover.typ`) | `estimated_cost` | The live estimated cost appears. Existing cover location/title literals are layout text and are not currently live runtime obligations. |
| Full project book (`projectPrintBook.ts`) | The above contracts for each included part | Each part uses unique input namespaces; annotated JSON shadow files and `sys.inputs` must agree. Never let one component's marker satisfy another component. |

The inventory deliberately does not promise that every scalar field or every pixel was verified. For example, document table paragraphs are currently checked as records, not individual cells. Floating images, signatures, arbitrary new optional features and every dimension within a drawing require additional explicit acceptance rules before claiming coverage. `worksheetTypst.ts` produces static worksheet source; it is not a live-data checklist provider. When a new frontend feature introduces printable content, add its obligation here and in the executable checklist, even if old templates lack the corresponding loop entirely.

## Render evidence

The compiler returns `printedContent`, collected by querying Typst metadata from the completed document. Source references, comments, unused functions, variables assigned but never output and false branches are not evidence. Markers do not appear on the PDF or change its paper/margins.

During an audited compile, the application clones JSON inputs and adds `_ee_print_id` to required records. The saved source is not modified. Emit metadata next to the corresponding visible content, inside the same conditional or loop:

```typst
#metadata("ee-print-audit:v1")
#for item in Bund.payable_by_code [
  #item.code
  #metadata(item.at("_ee_print_id", default: ""))#item.total #item.unit
  #for term in item.terms [
    #term.label: #metadata(term.at("_ee_print_id", default: ""))#term.quantity
  ]
]
```

Do not place markers in a separate checklist loop, or leave them behind when removing the visible content. Metadata is a cooperative rendering contract, not independent proof that text is legible: white text, clipping, dishonest markers and manually substituted wrong values are not detected by this version. A future visual/value audit may supplement it; do not describe metadata alone as that stronger guarantee.

Older compilers or layouts without audit evidence report **Unable to verify**. For templates declaring v1, absent record evidence is reported as **No printing marker found**, not an assertion that a PDF text search proved absence. Complete verified contracts have no Issues button. Failed, stale or uncompiled previews must not show a successful audit. Copy to AI includes readable labels, exact data paths, current values and marker instructions.

## Required maintenance audit for future AIs

1. Inventory the actual current `.typ` templates and adapters; follow their frontend inputs and intentional print selections. Do not simply register all JSON keys.
2. For every added/removed printable frontend feature, update the explicit obligation builder and this acceptance table. Include human-readable names, expected quantities/units and per-record scope. Keep layout-only and calculation-only variables excluded.
3. Place evidence at the actual rendering site; review all branches and collection filters. If a summary is accepted instead of details, define that acceptance explicitly and test it.
4. Preserve saved templates. New obligations must be detected from updated data even when old source never mentions the new variable. Never fix omissions by silently injecting built-in layout into custom source.
5. Run `node scripts/test-print-content-audit.cjs` and affected existing Typst tests. Add cases for newly added content, duplicate values/codes, omitted records, false branches, legacy source, no data, zero values, frontend exclusions and project-book namespaces.
6. Check saved source round-trips through `.eestimate`, canceled/failed saves remain unsaved, Use default remains separate, and changing current values does not rewrite source. Run renderer typecheck and desktop compiler checks; distinguish unrelated baseline failures.
7. Bump the contract version when acceptance changes incompatibly. Update marker guidance and compatibility handling together; do not claim older custom layouts have adopted the new contract automatically.
